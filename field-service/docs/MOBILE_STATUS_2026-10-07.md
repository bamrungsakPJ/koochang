# สถานะแอปมือถือ — 2026-10-07

ตรวจโค้ดและการตั้งค่า staging แบบอ่านอย่างเดียว ไม่ได้ทดสอบบนโทรศัพท์จริงในรอบนี้ และไม่ได้แก้โค้ดหรือ build ใหม่

## สิ่งที่มีแล้ว

Android รุ่นล่าสุด 0.2.5 / Build 7 มี APK ที่เซ็นแล้วใน `output/builds/apk/KooChang-0.2.5-build7.apk` ระบบหลักมีสมัคร/เข้าสู่ระบบ ร้านและทีม ลูกค้าและสถานที่ พิกัด อุปกรณ์ งาน ผลบริการ รอบดูแล สมาชิก/ชำระเงิน กล่องแจ้งเตือน และไทย/อังกฤษ

การอ่านป้ายมีสถานะและผลยี่ห้อ รุ่น Serial พร้อมลองใหม่ การจำ session และ biometric แบบเลือกเปิดมีโค้ดแล้ว เลขเวอร์ชันและ About ถูกนำออกตามคำสั่งผู้ใช้ ไม่ใช่งานค้าง

Claude ใช้ `claude-haiku-4-5-20251001` จำกัดผลตอบ 512 tokens และอ่านเฉพาะสามข้อมูล ทดสอบ API กับภาพสังเคราะห์จริงผ่านแล้ว แต่ยังไม่ได้ยืนยันเส้นทางถ่ายรูปบนมือถือจริงครบวงจร

## งานโค้ดและข้อจำกัดที่เหลือ

1. **โหลดรายการเพิ่มเติม**: mobile API และหน้ารายการไม่มี limit/offset หรือโหลดหน้าถัดไป Backend ให้ลูกค้าเริ่มต้น 30 รายการ งาน 200 รายการต่อคำค้น/ตัวกรอง จึงอาจเห็นรายการไม่ครบ ต่างจากเว็บที่แบ่งหน้าแล้ว (`apps/mobile/src/api.ts`, `screens/customers.tsx`, `screens/jobs.tsx`)
2. **เลือกวันและเวลานัด**: WhenPicker เลือกวันนี้และอีก 6 วันเท่านั้น เวลาเป็นชุดเต็มชั่วโมงที่กำหนดไว้ ยังเลือกวันที่ไกลกว่านั้นหรือเวลาเช่น 09:30 ไม่ได้ (`screens/jobs.tsx`)
3. **ออฟไลน์**: มีร่างผลบริการในเครื่อง แต่ยังไม่มี cache ข้อมูลเครื่องและคิวรูปสำหรับส่งเมื่อกลับออนไลน์ การเปิดฟอร์มและส่งรูปยังพึ่งเครือข่าย (`src/drafts.ts`, `screens/service.tsx`)
4. **แยกร่างตามผู้ใช้**: draft key ผูกกับร้านและงาน/สถานที่ ไม่ได้ผูกบัญชีผู้ใช้ และออกจากระบบไม่ได้ล้างร่าง ต้องแก้หรือยืนยันการแยกข้อมูลเมื่อใช้โทรศัพท์ร่วมกัน (`screens/service.tsx`)
5. **ส่งสลิปบนมือถือ**: ยังใช้ fetch(uri).blob() ต่างจากการส่งรูปป้ายที่แก้เป็น native bytes แล้ว ต้องตรวจหรือปรับให้สอดคล้องกัน ยังไม่มีหลักฐานว่าการส่งสลิปวิธีนี้ล้มเหลวจริง (`screens/billing.tsx`)
6. **Biometric**: ปลดล็อกตอนเริ่มแอป มีโค้ดแล้ว แต่ยังไม่มีการล็อกใหม่เมื่อกลับจาก background และยังไม่ได้ทดสอบ fingerprint/Face ID บนอุปกรณ์จริง

## การตั้งค่าและการส่งมอบที่เหลือ

- **Push**: มี FCM Android adapter แต่ไม่พบ google-services.json ในแหล่ง build ล่าสุด และไม่พบ service account ของ worker บน staging จึงยังไม่พร้อมยืนยันการรับ Push จริง; iOS Push ยังไม่รองรับ (`src/push.ts`, `docs/PUSH_FCM.md`)
- **SMS**: staging ปัจจุบันเลือก `SMS_PROVIDER=thsms` แม้ผู้ใช้เลือก DeeSMSx ต้องยืนยัน/ปรับค่าที่ใช้งานและทดสอบ OTP จริง ห้ามถือว่ามี adapter แล้วเท่ากับส่งผ่าน DeeSMSx อยู่
- **ชำระเงินจริง**: มี EasySlip และ Stripe flow แล้ว แต่ยังต้องทดสอบสลิปจริง ผลผ่าน/ผิดพลาด การเปิดสิทธิ์ทันที และกลับเข้าแอปหลังจ่ายเงิน ไม่มีการส่งเงินหรือ SMS จริงในรอบตรวจนี้
- **Android UAT**: ต้องติดตั้ง APK ล่าสุด ตรวจถ่าย/เลือกรูป → อัปโหลด → สถานะ AI → ผล/อ่านไม่ได้/ลองใหม่, GPS/permission, session หลังปิดเปิดและอัปเดต, biometric, ร่าง/เน็ตหลุด, keyboard/ขนาดตัวอักษร และชำระเงิน
- **iOS และร้านแอป**: ยังไม่มี build และผลทดสอบ iOS จริง รวมถึงการปล่อย App Store/Google Play

## ลำดับแนะนำ

แก้โหลดเพิ่มและวันนัด → แยกร่างตามผู้ใช้/ตรวจส่งสลิป → ตั้งค่า Push และยืนยัน SMS → ทดสอบ Android ครบวงจร → เตรียม iOS และปล่อยร้านแอป ออฟไลน์เต็มรูปแบบต้องยืนยันขอบเขตเพิ่มเติมก่อนขยายงาน

เอกสารเก่าที่ระบุว่าโค้ดมือถือครบแล้ว หรือยังไม่มีโดเมน/Anthropic key เป็นสถานะในอดีต ให้ใช้รายการนี้สำหรับการตรวจมือถือปัจจุบัน ไม่ถือว่ามีหน้าจอหรือผ่าน typecheck แล้วเท่ากับผ่าน UAT
