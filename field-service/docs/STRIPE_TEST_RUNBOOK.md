# คู่มือตั้งค่า Stripe และทดสอบการชำระเงินบน staging (2026-10-08)

ตกลงกับเจ้าของผลิตภัณฑ์แล้ว: **ทำ Stripe test mode ให้ครบก่อน แล้วค่อยทดสอบ live** ด้วยบัตรจริงราคาต่ำ
ใช้แพ็กเกจทดสอบ **20 บาท/เดือน** และกด**หยุดขายแพ็กเกจ (archive) ทันทีเมื่อทดสอบเสร็จ** เพราะทุกร้านบน staging (รวมร้าน beta) มองเห็นแพ็กเกจนี้

- staging: เว็บ/คอนโซล `https://app-staging.koochang.com` · API `https://api-staging.koochang.com`
- ทุกขั้นที่ใส่ key หรือรหัสผ่าน **เจ้าของบัญชีทำเอง** ห้ามส่ง secret key หรือ `whsec_` ทางแชต
- ชื่อเมนูใน Stripe Dashboard อาจต่างเล็กน้อยตามรุ่นของหน้าจอ ให้ยึดชื่อสิ่งที่ต้องตั้งเป็นหลัก

## ส่วน A — เตรียม server (ทำครั้งเดียว)

**A1. แก้ที่อยู่กลับหลังชำระเงิน** ตอนนี้ `OWNER_WEB_URL` ไม่มี `/shop` ทำให้ Stripe พากลับไปหน้าเว็บหลักแทนหน้าร้าน
รันบน server2 (ต้องใช้ sudo จึงต้องเป็นเจ้าของ server ทำเอง):

```bash
ssh uht-dev
sudo sed -i 's#^OWNER_WEB_URL=.*#OWNER_WEB_URL=https://app-staging.koochang.com/shop#' /etc/field-service/staging.env
pm2 restart fs-staging-api fs-staging-worker
```

**A2. เปิดรับชำระเงินใหม่** คอนโซล → **นโยบายระบบ** → ต้องติ๊ก "เปิดสร้างใบแจ้งชำระใหม่" ไว้ (ถ้าปิด ร้านจะเห็นว่าชำระไม่ได้)

## ส่วน B — Stripe Dashboard (test mode)

**B1. สลับเป็นโหมดทดสอบ** เข้า [dashboard.stripe.com](https://dashboard.stripe.com) → เปิดสวิตช์ **Test mode**
(บัญชีใหม่อาจเรียกว่า **Sandbox**) ทุกขั้นในส่วน B ต้องทำในโหมดนี้

**B2. เปิดวิธีชำระเงิน** Settings → Payments → **Payment methods** → เปิด **Cards** และ **PromptPay**
(PromptPay ใช้ได้เฉพาะบัญชี Stripe ประเทศไทยที่ตั้งสกุลเงิน THB)

**B3. คัดลอก Secret key** Developers → **API keys** → Secret key ที่ขึ้นต้นด้วย `sk_test_` → กด Reveal แล้วคัดลอกเก็บไว้ชั่วคราว (ยังไม่ต้องใส่ที่ไหน)

**B4. ดูที่อยู่ปลายทางของ webhook จากคอนโซล** คอนโซลคู่ช่าง → **ตั้งค่าการชำระเงิน** → วาง secret key ลงช่อง
"Secret key ของ Stripe" (**ยังไม่ต้องกดบันทึก**) → คัดลอกที่อยู่ในช่อง **"ปลายทางรับผลชำระจาก Stripe"**
รูปแบบจะเป็น `https://api-staging.koochang.com/v1/billing/stripe/webhook/<รหัส>`
> ที่อยู่นี้เปลี่ยนทุกครั้งที่ใส่ key ชุดใหม่ ต้องคัดลอกหลังวาง key แล้วเท่านั้น

**B5. สร้าง webhook ใน Stripe** Developers → **Webhooks** → **Add endpoint** (หรือ Add destination → Webhook endpoint)
- Endpoint URL: ที่อยู่จาก B4
- API version: ใช้ค่าตั้งต้น
- เลือก events ให้ครบ **8 ตัว**:

| event | ใช้กับ |
|---|---|
| `checkout.session.completed` | จ่ายครั้งเดียว / เริ่มสมัครตัดบัตร |
| `checkout.session.async_payment_succeeded` | PromptPay ยืนยันภายหลัง |
| `checkout.session.async_payment_failed` | PromptPay ไม่สำเร็จ |
| `checkout.session.expired` | หน้าชำระหมดอายุ |
| `invoice.paid` | ตัดบัตรอัตโนมัติสำเร็จแต่ละรอบ |
| `invoice.payment_failed` | ตัดบัตรไม่สำเร็จ |
| `customer.subscription.updated` | สถานะการสมัครเปลี่ยน |
| `customer.subscription.deleted` | การสมัครถูกยกเลิก |

กดสร้าง แล้วเปิด endpoint ที่สร้าง → **Signing secret** → Reveal → คัดลอกค่า `whsec_...`

**B6. ให้ Stripe ยกเลิกเมื่อตัดเงินไม่สำเร็จ** Settings → Billing → **Subscriptions and emails** → Manage failed payments
- เปิด Smart Retries (หรือกำหนดจำนวนครั้งที่ลองใหม่)
- "If all retries for a payment fail" → เลือก **Cancel the subscription**
  (ระบบเราจะแจ้งร้าน "หยุดตัดบัตรอัตโนมัติแล้ว กรุณาชำระเอง" เมื่อ Stripe ยกเลิก)

**B7. เปิด Customer portal** Settings → Billing → **Customer portal**
- เปิด: อัปเดตวิธีชำระเงิน (Payment methods) และ ดูประวัติใบแจ้งหนี้ (Invoice history)
- **ปิด** การยกเลิก subscription ในพอร์ทัล — ให้เจ้าของร้านยกเลิกผ่านปุ่มในแอปของเรา ระบบจะได้รู้ว่าเป็นการยกเลิกเอง
- **ปิด** การเปลี่ยนแพ็กเกจ (Switch plans / Subscription updates) และการเปลี่ยนจำนวน (Update quantities) — ราคากำหนดจากคอนโซลเท่านั้น ถ้าเปิดไว้ ลูกค้าจะเปลี่ยนยอดตัดบัตรเองได้ ระบบจะกันการต่ออายุ (PAYMENT_MISMATCH) แต่ต้องตามแก้ด้วยมือ
- ไม่ต้องสร้าง Product / Price ใน Stripe Dashboard — ระบบส่งราคาจากแพ็กเกจในคอนโซลให้ Stripe เองตอนชำระเงิน
- กด Save / Activate test link

## ส่วน C — คอนโซลคู่ช่าง

**C1. บันทึกกุญแจ** คอนโซล → **ตั้งค่าการชำระเงิน**
- Secret key ของ Stripe: `sk_test_...` (จาก B3, วางไว้แล้วใน B4)
- Webhook signing secret: `whsec_...` (จาก B5)
- ติ๊ก **เปิดรับบัตรเครดิต / เดบิต** และ **เปิดรับ QR PromptPay**
- กด **บันทึก** → ใส่รหัส 6 หลักจากแอป authenticator
- ผลที่ควรเห็น: รหัสบัญชี `acct_...`, โหมด **ทดสอบ** และสถานะว่าตั้งค่าแล้ว
- ถ้าขึ้นว่าบันทึกไม่ได้: ตรวจว่า key กับ webhook มาจากบัญชีและโหมดเดียวกัน

**C2. สร้างแพ็กเกจทดสอบ** คอนโซล → **แพ็กเกจและราคา** → อ่านกล่องคู่มือ → **สร้างร่าง**

| ช่อง | ค่า |
|---|---|
| รหัสแพ็กเกจ | `test20` |
| ชื่อไทย | `ทดสอบระบบ (ห้ามเลือก)` |
| ชื่ออังกฤษ | `System test (do not choose)` |
| ประเภทแพ็กเกจ | ชำระเงิน |
| จำนวนช่าง | 1 |
| พื้นที่รูป (GB) | 1 |
| วันทดลอง | 0 |
| วันผ่อนผัน | 3 |
| ราคา/เดือน (บาท) | 20 |
| ราคา/ปี | เว้นว่าง |
| เริ่มมีผล | เวลาปัจจุบัน |

กดบันทึก → ในรายการร่าง กด **เผยแพร่ทันที** (super_admin) หรือ **ส่งขออนุมัติ** แล้วให้อีกคนอนุมัติที่ **คำขออนุมัติ**
→ ตรวจว่าแพ็กเกจขึ้นในรายการพร้อมเวอร์ชัน 1 · 20 บาท/เดือน

## ส่วน D — ทดสอบ (test mode)

ใช้ร้านทดสอบที่เป็นเจ้าของเอง (แอปมือถือหรือ `https://app-staging.koochang.com/shop`) ทุกหน้าชำระต้องมีป้าย
**"Stripe test mode — ไม่มีการชำระจริง"** ถ้าไม่มีให้หยุดทดสอบ

บัตรทดสอบของ Stripe (วันหมดอายุใส่วันในอนาคตอะไรก็ได้, CVC 3 หลักอะไรก็ได้):
- `4242 4242 4242 4242` — สำเร็จ
- `4000 0000 0000 0002` — ถูกปฏิเสธ
- `4000 0000 0000 0341` — ผูกบัตรได้ แต่ตัดเงินรอบถัดไปไม่สำเร็จ

| # | ทำอะไร (ฝั่งร้าน) | ผลที่ร้านควรเห็น | ตรวจฝั่งคอนโซล / Stripe |

| D2 | ใบแจ้งชำระใหม่ → **QR Code พร้อมเพย์** | หน้าทดสอบของ Stripe มีปุ่มจำลองว่าชำระสำเร็จ → กด → ชำระแล้ว | เหมือน D1 แต่ช่องทาง PromptPay |

## ส่วน E — ทดสอบ live (เงินจริง หลังส่วน D ผ่านครบ)

1. บัญชี Stripe ต้องผ่าน onboarding ครบ (ข้อมูลธุรกิจ, บัญชีธนาคารรับเงิน) และเปิด Cards/PromptPay ใน **live mode**
2. ทำซ้ำ B2–B7 ในโหมด live (ได้ `sk_live_...` และ webhook endpoint/secret ชุดใหม่ของ live) แล้วทำ C1 ด้วย key live
   — **ที่อยู่ปลายทางจะเปลี่ยน** ต้องคัดลอกใหม่ใน B4; ปลายทาง test เดิมเก็บไว้ได้จนรายการเดิมจบ
3. ถ้าหยุดขายแพ็กเกจทดสอบไปแล้ว ให้สร้างแพ็กเกจทดสอบใหม่ (เช่น `test20live`) ตามข้อ C2
4. ทดสอบเฉพาะ D1 (บัตรจริง 20 บาท), D2 (สแกน QR จริง 20 บาท) และ D5→D8 ถ้าต้องการ
5. คืนเงินทดสอบใน Stripe Dashboard (Payments → รายการ → Refund) — ระบบเรายังไม่ดึงการคืนเงินจาก Stripe อัตโนมัติ
   ให้บันทึกการคืนเงินในคอนโซลเพื่อให้ยอดกระทบตรงกัน
6. ค่าธรรมเนียม Stripe ของรายการจริงไม่คืนเมื่อ refund

## ส่วน F — หลังทดสอบ

1. คอนโซล → แพ็กเกจและราคา → แพ็กเกจทดสอบ → **หยุดขายแพ็กเกจ** (ร้านใหม่จะไม่เห็นอีก)
2. ร้านที่ยังสมัครตัดบัตรอัตโนมัติกับแพ็กเกจทดสอบ ให้กด **ยกเลิกตัดบัตรอัตโนมัติ** (แพ็กเกจที่หยุดขายแล้ว Stripe ยังตัดราคาเดิมต่อ)
3. บันทึกผลแต่ละข้อ (ผ่าน/ไม่ผ่าน + INV + เวลา) ลง `docs/PROGRESS_LOG.md`
