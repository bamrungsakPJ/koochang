# เว็บเจ้าของร้าน — 2026-10-04

พื้นที่ร้านอยู่ที่ `/shop` ใน Next.js แอปเดียวกับ `/console` แต่ใช้บัญชีร้านผ่าน OTP และ session แยกจากทีมแพลตฟอร์ม หน้าแรก `/` เปิด `/shop` โดยตรง เว็บเรียก API จริงและฐานข้อมูลเดียวกับแอปมือถือ ไม่มีข้อมูลร้านจำลองในหน้าผลิตภัณฑ์

## ขอบเขตที่พัฒนาแล้ว

- เข้าสู่ระบบด้วยเบอร์โทร/OTP สร้างร้านเพิ่ม สลับร้านของเจ้าของ และตั้งชื่อ/ภาษาไทยหรืออังกฤษ
- ภาพรวมงาน รอบดูแล คำขอร่วมทีม การแจ้งเตือน และโควตาสมาชิก
- ทีมช่าง: ลิงก์/QR เปิด–ปิด/รีเซ็ตลิงก์ อนุมัติ ปฏิเสธ ระงับ คืนสิทธิ์ และถอดสมาชิก
- ลูกค้า: ค้นชื่อ/เบอร์ เพิ่ม/แก้ไข เก็บถาวร เตือนข้อมูลซ้ำ หลายสถานที่ ที่อยู่และทางไป
- พิกัดสถานที่: กรอกเอง หรือกดใช้ตำแหน่งปัจจุบันแล้วตรวจค่าก่อนบันทึก ไม่ติดตามช่าง; ต้องยืนยันเมื่อแทนพิกัดเดิม
- อุปกรณ์: เพิ่ม/แก้ไข รูปป้าย/รูปเครื่อง OCR เป็นข้อเสนอที่ผู้ใช้เลือกใช้ ตรวจ serial ซ้ำ และประวัติบริการรายเครื่อง
- งาน: กรองสถานะ/ผู้รับผิดชอบ/วัน สร้างแผน เลือกเครื่อง มอบหมายให้ตัวเองหรือช่าง แก้แผน เปลี่ยนผู้รับผิดชอบ เลื่อนนัด ยกเลิก เริ่มงาน และแสดงประวัติ
- ผลบริการ: งานที่มอบหมายหรือบันทึกหน้างาน รายเครื่องทำแล้ว/ไม่ได้ทำ/เลื่อนพร้อมเหตุผล รูปก่อน–หลัง หมายเหตุ และกำหนดรอบดูแลถัดไป
- รอบดูแล: เลยกำหนด/7 วัน/30 วัน บันทึกติดต่อ นัดรวมเครื่องในสถานที่เดียวกัน เลื่อนรอบหรือหยุดเตือน
- สมาชิก: สถานะ/โควตา/แผน เลือกแพ็กเกจ ใบแจ้งชำระ พิมพ์ ส่งสลิป ดูผลตรวจ และหยุด/กลับมาต่ออายุเมื่อสถานะอนุญาต
- ซัพพอร์ต: เปิดเรื่อง ตอบกลับ ยินยอม/ปฏิเสธ/เพิกถอนสิทธิ์อ่านข้อมูลตามขอบเขตและเวลา ขอส่งออกข้อมูล และอ่านการแจ้งเตือน

## พฤติกรรมสำคัญ

API ตรวจสิทธิ์จริงทุกคำสั่ง เว็บเปิดเมนูธุรกิจเฉพาะเจ้าของที่ active ร้านถูกระงับยังติดต่อซัพพอร์ตได้ บัญชีช่างใช้แอปมือถือ การส่งสลิปไม่ต่ออายุเอง ต้องให้แพลตฟอร์มยืนยันยอดรับจริง

เวลานัดที่กรอกเป็น Asia/Bangkok ไม่ขึ้นกับ timezone เครื่อง ภาษาใช้ shared catalogs; ไทยแสดงปี พ.ศ. และเงิน THB

Token ร้านอยู่ใน sessionStorage ของแท็บ แยกจาก `console.session`; โหลดหน้าใหม่และ API ขาดการเชื่อมต่อชั่วคราวไม่ทำให้บัญชีหลุด ปิดแท็บแล้วต้องเข้าสู่ระบบใหม่ ไม่มี service worker หรือเว็บออฟไลน์เต็มรูปแบบ

ร่างผลบริการอยู่ใน localStorage แยกร้าน/สมาชิก/งาน เก็บ 7 วันและกู้คืนเมื่อกลับหน้าเดิม ใช้ event id เดิมเมื่อส่งซ้ำและคงคำสั่งเดิมเมื่อยังไม่ทราบผล ลบร่างเมื่อ API ยืนยันสำเร็จ รูปต้องอัปโหลดออนไลน์ก่อน; ไม่ควรใช้เครื่องสาธารณะเก็บร่างข้อมูลลูกค้า

รายการลูกค้าแสดงสูงสุด 100 ต่อการค้นหา งานสูงสุด 200 ตามข้อจำกัด API ปัจจุบัน ใช้ค้นหา/ตัวกรองวันเพื่อจำกัดรายการ ยังไม่มี pagination และ export สำหรับรายการบนหน้าจอ การขอส่งออกข้อมูลร้านเป็นคำขอให้ทีมแพลตฟอร์มดำเนินการ

## วิธีรัน

ตั้ง API/ฐานข้อมูลตาม README จากนั้น `pnpm dev:api` และ `pnpm dev:admin` เว็บอยู่ `http://localhost:3001/shop` ตั้ง `NEXT_PUBLIC_API_URL` ใน `apps/admin/.env.local` ให้ชี้ API และอนุญาต origin เว็บใน API; พิกัดนอก localhost ต้องใช้ HTTPS

สำหรับตรวจด้วยข้อมูลสังเคราะห์โดยไม่แตะร้านจริง:

```sh
pnpm build:packages
pnpm --filter @field-service/api build
node --env-file=.env scripts/owner-web-test-server.mjs
```

ต้องมี `TEST_DATABASE_URL` ที่เป็น loopback และชื่อฐานลงท้าย `_test` ตัวช่วยสร้างใหม่เฉพาะฐาน `<base>_owner_web_test` บน cluster ทดสอบแยก เปิดเว็บ `http://127.0.0.1:3101/shop` กับ API `4101` และอ่าน OTP จาก development SMS log ไม่มีส่ง SMS จริง ใช้ข้อมูลธนาคารสังเคราะห์และไฟล์ชั่วคราว กด Ctrl+C เพื่อปิด ต้องปิดตัวช่วยก่อนรัน HTTP test suite เพราะชุดทดสอบเปลี่ยนรหัส role `fs_api` ใน cluster ทดสอบ
